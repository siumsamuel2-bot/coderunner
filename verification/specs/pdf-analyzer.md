# Verification spec: PDF analyzer

Challenge: "Build a tool that accepts a PDF and extracts text/metadata" (SPE-55 #3).

## What "working" means

A submission passes when **all required checks below pass** against the live URL. The harness uploads a known fixture PDF through the UI and asserts the extraction output.

## The fixture

`fixtures/sample.pdf` - a deterministic, valid, single-page PDF generated by `fixtures/make-pdf.ts`. Its text layer contains the marker phrase `VERIFICATION FIXTURE ALPHA` plus supporting copy, and it has exactly 1 page.

## The contract (discovery rules)

- The app must expose a standard **`<input type="file">`** for the upload (it may be visually hidden behind a styled button). Any API the app calls internally is irrelevant.
- Extracted text must appear in the rendered page within 30 seconds of upload.
- Metadata display must include at least one of: **page count** (1), **file name** (`sample.pdf`), or **file size** (in bytes/KB/MB).

## Required checks

| id | passes when |
|---|---|
| `pdf-page-loads` | Target URL returns HTTP < 400 |
| `pdf-file-input` | A file input exists on the page |
| `pdf-extracts-text` | After upload, the marker phrase `VERIFICATION FIXTURE ALPHA` appears in the page text |
| `pdf-metadata` | A page-count, file-name, or file-size signal is displayed |
| `pdf-no-console-errors` | Zero `console.error` / uncaught page errors during the session |

## Bonus checks (do not affect the verdict)

| id | passes when |
|---|---|
| `pdf-shows-filesize` | A file size indicator (bytes/KB/MB) is displayed |

## Anti-mock design

The marker phrase exists only inside the fixture PDF's content stream. A submission cannot pass without actually reading and extracting text from the uploaded file (the filename alone does not contain the marker).
